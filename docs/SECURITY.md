# Security

BrainOutside holds your notes and four credentials that can read or
rewrite them. This document is the honest version: what the server
protects, how, and — the part that matters more — what it does not
protect and cannot.

It is written for someone about to put this on a VPS.

---

## Reporting a vulnerability

Email the address in `SECURITY_TXT_CONTACT`. If you are reading this in
the public repository and want to report something against the project
rather than against someone's install, open a GitHub security advisory
on the repository — not a public issue.

A deployed server publishes `/.well-known/security.txt` (RFC 9116) when
`SECURITY_TXT_CONTACT` is set, and returns 404 when it is not. There is
no fake contact address baked in.

---

## The one sentence that matters

**A `private` note is exactly as private as the machine you run this
on.** Notes sit in a git clone on disk, in per-tier snapshot directories
on disk, and in Postgres. Nothing is encrypted at rest beyond the
credential columns. Anyone with root on that host, or a copy of that
volume, has your brain. Everything below is defence in depth behind that
fact — not a substitute for it.

---

## The four credentials

| Credential | What it can do | Where it lives |
|---|---|---|
| **Deploy key** (ed25519, read-only) | Clone and pull your brain repo | Generated by the server; private half encrypted in Postgres, or mounted via `BRAIN_GIT_SSH_KEY_PATH` |
| **Write PAT** (GitHub, fine-grained) | Push approved commits to your brain repo | `BRAIN_GIT_WRITE_PAT`, or a file at `BRAIN_GIT_WRITE_PAT_PATH`, or encrypted in Postgres |
| **Anthropic key** | Spend money on your account | Encrypted in Postgres, or `ANTHROPIC_API_KEY` in the environment |
| **Webhook secret** | Trigger a sync | `GITHUB_WEBHOOK_SECRET`, or generated in the ops UI and stored encrypted |

Read and write are **separate credentials on purpose**. A stolen read
key leaks your brain; a stolen write key rewrites it, and a rewritten
brain is one you may not notice for weeks. The wizard's deploy-key step
tells you to leave "Allow write access" unchecked for this reason.

### Environment beats the database

For the write PAT and the Anthropic key, an environment variable or a
mounted file **wins over** the stored value, and the ops UI says so when
one is present. Use that if you would rather the credential never touch
Postgres: a database dump then carries no push access.

The tradeoff is real in both directions. In the database, the credential
is encrypted at rest and rotatable from the ops UI without a redeploy.
In the environment, it is in your hosting panel and in the process
environment of every container that inherits it, and changing it means a
redeploy — but it is not in your backups.

### Encryption at rest

Credential columns are encrypted with `FIELD_ENCRYPTION_KEY`. That
protects a **database dump**, not a compromised host: the key is in the
environment of the process that can decrypt them.

`FIELD_ENCRYPTION_KEY` is generated on first boot and persisted to
`BRAIN_STATE_DIR`, which **must** be a durable volume. If it changes,
every stored credential becomes undecryptable and reads back as empty —
the failure looks like "my settings were wiped", not "the key changed".
The server refuses to boot rather than silently regenerate it.

To rotate it deliberately, use `manage.py rotate_field_encryption_key`,
which re-encrypts the stored values rather than orphaning them.

## Visibility tiers

Notes carry `visibility: public | agents-only | private`. The boundary is
**structural, not a filter**: the indexer materialises one snapshot
directory per tier, and a caller's credential picks the directory. A
public-tier caller is not "shown less" — the notes it may not see are not
in the filesystem it is reading.

The reader agent runs against exactly one snapshot, with `Read` scoped to
that directory, `Grep`/`Glob` confined by a `PreToolUse` hook, and
everything else (`Bash`, `Write`, `WebFetch`, `Task`, …) denied by name so
the tools never enter its context at all. The hook is not optional: a
tool allowed without a path specifier is allowed outright, and `cwd` does
not constrain an absolute path argument.

An unrecognised stored tier reads as `public` — the least-privileged
answer, not an error that might fail open.

## Writes are gated on a human

Nothing writes to your brain without you. A proposal arrives (from the
feeder agent, or pasted), is validated, and sits in an approval queue
rendered **as a diff, not as executed markdown**. Approving it produces a
signed commit. There is no auto-approve, and there is no path from an
API call to a commit.

This is the control that contains prompt injection. Fed URLs and
transcripts are attacker-influenceable input to an agent, and no amount
of prompting makes that safe. Injected content can still shape a
*proposal* — the human gate is what stops it becoming a commit, which is
why the approval UI shows you a diff instead of something pretty.

The validator is a backstop, not the defence. Its rules include path
containment (a proposal may only touch content surfaces), no deletions,
and a rule that a proposal must not quote content from a `private` note —
an anti-exfiltration check for the case where a lower-tier agent has
somehow seen something it should not have.

## The ops UI is the crown jewels

`/ops/` can approve feeds, read every private note, and read and rotate
every credential. Treat it as the most sensitive surface on the box.

- It is staff-only and behind Django auth.
- `ADMIN_PANEL_URL_PATH` moves it off a guessable path. This is not a
  security control by itself — it removes it from bot scan lists.
- `ADMIN_IP_ALLOWLIST` restricts it to CIDRs you name. Behind a proxy
  this is compared against the resolved client IP, which means
  `TRUSTED_PROXY_IPS` and `TRUSTED_PROXY_IP_HEADER` must be set
  correctly or the check is comparing against your proxy.
- **Put the whole prefix behind a network boundary.** Tailscale,
  Cloudflare Access, or a VPN. That is the intended deployment, and the
  IP allowlist is the fallback for when it is not available.

Failed staff logins feed a lockout counter, and crossing the threshold
raises an alert. Alerts currently go to the console backend, which means
your container log — wiring real delivery is a deliberate change, not a
setting.

The first-run wizard's account step is open to anyone who can reach the
server **until the first operator account exists**, because something has
to bootstrap the first identity without a terminal. That window is one
page wide (no other step is reachable), it closes permanently the moment
you create the account, and the app logs a loud warning the first time
anything reaches it while the window is still open — once per process,
not once per request, so it is visible rather than buried. Create your
account before you point DNS at the box.

## The public surfaces

Only three things are meant to be reachable from the internet: the REST
API under `/api/`, the MCP endpoint under `/mcp`, and the GitHub webhook.

- **API keys** are stored as SHA-256 hashes. The plaintext is shown once
  at creation and never again. Each key carries a tier.
- **Rate limits** are per-credential, with an anonymous per-IP backstop.
  The anonymous limit is only meaningful once `TRUSTED_PROXY_*` is
  configured — without it every anonymous caller shares the proxy's
  bucket.
- **Repeated auth failures** lock a credential prefix out, separately for
  API keys and URL tokens.
- **The webhook** is HMAC-verified with a timing-safe comparison and is
  disabled (403 on every delivery) when no secret is set. It is never
  open by default.

### Connector URLs carry a credential in the path

The `/mcp/k/<token>/` surface exists because that is the shape claude.ai
web and mobile accept. A URL-embedded credential is in `request.path`,
which means it is a leak surface for every access log in the chain —
ours, uvicorn's, and whatever proxy sits in front.

The server scrubs the token out of the path before any logging
middleware sees it. Your **reverse proxy's** access log is outside its
reach, and you should configure that yourself. This surface is off by
default (`MCP_URL_AUTH_ENABLED=false`); turn it on when you need it and
know what you are turning on.

## Browser-side

Content-Security-Policy is **enforced**, including in development. That
is deliberate and not negotiable in this codebase: report-only mode hid a
release blocker for the life of the project, because a `style="…"`
attribute that prod drops renders fine locally. Inline scripts carry a
nonce; inline style attributes do not exist and a test fails the build if
one appears.

Also set: HSTS, `X-Content-Type-Options: nosniff`, `Referrer-Policy`,
`X-Frame-Options`, and a `Permissions-Policy` denying camera, microphone
and geolocation.

## What this does not protect

Stated plainly, because a security document that only lists wins is
marketing:

- **A compromised host.** Encryption at rest protects backups. The
  running process holds the keys.
- **Your notes in transit through Anthropic.** Chat, context assembly and
  feed extraction send note content to the API under your key. Use a
  workspace-scoped key with a spend limit.
- **SDK session transcripts.** The Claude CLI writes JSONL session files
  inside the container containing note content. Treat that volume as
  sensitive.
- **Your git host.** Your brain is a repository on GitHub. Its access
  controls are theirs, not ours.
- **Prompt injection reaching a proposal.** Contained by the human gate,
  not prevented.
- **Backups.** There are none unless you make them. Feeds, events, the
  SDK ledger and chat history are primary data and are not rebuildable
  from the repo. Encrypt them, put them somewhere else, and test the
  restore.

## A short deployment checklist

1. `POSTGRES_PASSWORD` and `ALLOWED_HOSTS` set; everything else has a
   working default.
2. `BRAIN_STATE_DIR` on a durable volume. Not a container filesystem.
3. Create the operator account before the box is publicly reachable.
4. `/ops/` behind a network boundary; `ADMIN_PANEL_URL_PATH` changed.
5. Deploy key read-only. Write PAT scoped to the one repository, with
   `Contents: read and write` and nothing else.
6. `GITHUB_WEBHOOK_SECRET` set, or accept that the webhook is off.
7. A workspace-scoped Anthropic key with a console spend limit, plus
   `DAILY_COST_CAP` as the in-app breaker.
8. `SECURITY_TXT_CONTACT` set, so someone who finds a problem can tell
   you.
9. Backups running, and a restore you have actually tried.
