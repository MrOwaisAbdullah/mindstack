Order matters: the SVG comes first because browsers that support it prefer it, and it is the only one that follows the OS light/dark scheme (see the media query inside the file). The .ico is the fallback for everything else and carries NATIVE 16/32/48 renders rather than one image downscaled — at 16px a downscale turns the fissure to grey mush. `sizes="any"` stops Chrome preferring the .ico over the SVG. {% endcomment %} {% comment %} Theme resolution. Everything for dark mode already existed — the `.dark` block in tokens.css, the compiled `dark:` utilities, the styleguide rendering both themes, the toggle partial — except the one line that reads the stored choice back. Nothing anywhere called `localStorage.getItem('theme')`, so `.dark` was never put on and the whole theme was dead. Deliberately NOT deferred, and placed above the body: it has to run before first paint, or every page load flashes light before repainting dark. That is also why it is inline rather than a static file — a blocking request for two dozen bytes of class toggling on the critical path is the wrong trade. No stored choice means follow the OS, which is what the toggle partial's comment has always claimed and nothing implemented. The matchMedia listener keeps that true if the OS flips mid-session, and stops applying the moment the visitor makes an explicit choice. {% endcomment %} {% block head_extra %}{% endblock %} {% block body %}{% endblock %}
